# 0069: A clipped summary is rebuilt automatically a while later

When the model returns no text for a summary, the node is saved as its source clipped to the node limit, so the chat goes on (asking again at once fails alike). Those clipped nodes, and every merge above them, are what `/unii repair` (ADR-0065) reports. With v0.2.7 they still turned up now and then (about one call in a hundred on `openai/gpt-6-luna`, even with tool use forbidden, ADR-0067), so chats kept asking for a manual repair. On 2026-11-04 every flag in `ses_ebd90e1d4ffeJhdzBrlonXc21i` was such a node or a merge built on it: none were false positives.

So a saved clipped fallback schedules the same repair automatically, 60 s later. It drops the clipped node and the merges above it (archived as usual) and builds them again from the log. A node that falls back again is retried after 120 s, then 240 s; after three retries it stays clipped, and the status counts it again for `/unii repair`. One retry is scheduled at a time, and fallbacks saved while it waits join it. Until then the status does not count the clipped node, since it will fix itself. The retries are counted per open of the chat, not stored.
