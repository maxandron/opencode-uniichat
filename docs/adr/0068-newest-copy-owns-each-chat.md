# 0068: The newest copy of the plugin owns each chat

OpenCode loads a new copy of the package into the running server on an update or config reload, and the chat registry used to belong to each copy. A chat opened by the older copy kept its queue going in the background with the older code, while the new copy opened the same chat again: on 2026-10-31, after the hot reload to v0.2.6, the v0.2.5 queue of one chat went on building summaries for 20 minutes beside the new one, with tool calls v0.2.6 forbids (ADR-0067), and 931 nodes were written twice with different text. So the registry is shared by the whole process (`Symbol.for("opencode-uniichat.chats.v1")`), and each copy takes a number when it loads. The first `get` of a chat by a newer copy closes the older copy's Chat, which waits for its write in progress, drops the summaries still in flight and writes nothing more, then opens the chat again from the store. An older copy asking for a chat a newer one owns gets an error rather than a second Chat. Only plain promises cross copies, since each copy may bring its own Effect. Copies before v0.2.7 do not take part, so the first reload onto v0.2.7 still needs a restart.
